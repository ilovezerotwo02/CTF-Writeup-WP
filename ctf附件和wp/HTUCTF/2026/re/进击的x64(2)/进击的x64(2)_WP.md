# HTUCTF「进击的x64(2)」WP

- 分类：Reverse / 1000 分 / StaticAttachment
- 题目描述：对它使用x64dbg吧！
- 附件：`DualStageChallenge.exe`（935936B，MinGW-w64 编译的 x64 Windows 控制台程序）
- flag：`HTUCTF{dynamic_debug_xor_stage_complete}`

> 注：本题为两阶段口令门 + 静态 flag 生成。Stage A 口令动态（依赖 `GetTickCount64`），Stage B 口令与最终 flag 均为静态。

---

## 1. 总体思路

1. pefile 提取 PE 结构与 .rdata 中的提示字符串，扫 .text 里对这些字符串的 RIP 相对引用 → 锁定 `main`。
2. 顺着 `main` 的 call 链找到三个自定义函数：`check_A`、`check_B`、`generate_flag`（MinGW 的 iostream/printf 全部忽略）。
3. capstone 反汇编三函数，还原算法；pefile 提取 5 张数据表；纯 Python 复算。
4. `echo` 两阶段密码管道喂给 exe 动态验证 flag。

题目名/描述里的 "x64dbg" 是烟雾弹——完全静态可解；动态调试器只在需要现场看 Stage A 生成 buffer 时才用得上。

## 2. 程序结构

PE：`ImageBase=0x400000`，入口 `0x14f0`（CRT 启动），`.text` 0xb4050 字节（静态链接 libstdc++）。关键逻辑集中在 `0x401560–0x401af2`。

| 函数 | VA | 作用 |
|---|---|---|
| `check_A` | `0x401560` | Stage A 动态密码校验（13 字节） |
| `check_B` | `0x401686` | Stage B 循环 XOR 密码校验（14 字节） |
| `generate_flag` | `0x401730` | 生成并打印 40 字节 flag |
| `main` | `0x401824` | 打印 banner → 读密码 → 两阶段校验 → 打印 flag |

### main 流程（`0x401824`）

```
cout << banner / Stage A / hint / "Password: ";
getline(cin, s1);
if (!check_A(s1)) { cout << "[!] Stage A failed."; return 0; }
cout << "[+] Stage A unlocked." / Stage B / hint / "Stage B password: ";
getline(cin, s2);
if (!check_B(s2)) { ... return 0; }
cout << "[+] Flag: " << generate_flag() << endl;
```

## 3. Stage A：动态密码（`check_A @ 0x401560`）

反汇编要点：

```asm
0x40156c  mov  qword [rbp-0x10], 0xd          ; 期望长度 13
0x401574  mov  rax, [rip+0xe7019]             ; IAT: GetTickCount64 (VA 0x4e8594)
0x40157b  call rax
0x40157d  shr  rax, 0x14                      ; >>20（约 17 分钟变一次）
0x401581  xor  eax, 0xffffffa7
0x401584  mov  byte [rbp-0x11], al            ; seed
; 循环 i = 0..12 生成 buffer[13]：
0x4015ad  lea  rdx, [rip+0xb7a4c]             ; table1 @ 0x4b9000
0x4015bb  movzx eax, byte [table1 + i]
0x4015c5  add  eax, edx                       ; + seed
0x4015d1..0x4015de                            ; + i*11
0x4015e1  movabs rdx, 0x8fb823ee08fb823f      ; magic → % 57
0x40161b  lea  rdx, [rip+0xb7a5e]             ; table2 @ 0x4b9080
0x401629  movzx eax, byte [table2 + idx]
0x401637  mov  byte [buf+i], al
; 校验：
0x401647  call string::length                 ; == 0xd
0x40166b  call 0x418300                       ; memcmp(输入, 生成buffer, 13)
0x401670  test eax, eax / jne fail
```

`0x8fb823ee08fb823f` 乘法 + `shr 5` 是编译器对 **模 57** 的除法优化（验证：`q*57` 用 `q*8-q=q*7; q*7<<3=q*56; +q` 还原后相减）。

**公式：**

```
seed     = ((GetTickCount64() >> 20) ^ 0xA7) & 0xFF
passA[i] = table2[(table1[i] + seed + i*11) % 57]      i = 0..12
```

数据表（.rdata）：

- `table1 @ 0x4b9000`（13B）：`2d 1b 2a 63 1f 7f 0f 7f 1f 1c 2a 76 63`
- `table2 @ 0x4b9080`（57B）：`ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz23456789`（base58 风格字母表）

这就是 Hint 说的 "find the byte comparison (memcmp@0x40166b), then inspect the generated buffer (rbp-0x2d)"。x64dbg 里下断点看 buffer 即可拿到当次密码；静态则直接用上式（配合当前 `GetTickCount64`）。密码约每 1048576 ms（≈17.5 min）随 seed 变化一次。

## 4. Stage B：循环 XOR（`check_B @ 0x401686`）

```asm
0x401692  mov  qword [rbp-0x10], 0xe          ; 长度 14
0x40169a  mov  qword [rbp-0x18], 8            ; 密钥长 8
0x4016ab  cmp  rax, 0xe                       ; length() == 14
0x4016cc  lea  rdx, [rip+0xb793d]             ; ct2 @ 0x4b9010
0x4016e7  lea  rax, [rip+0xb7932]             ; key8 @ 0x4b9020
0x4016e1  and  eax, 7                         ; i % 8
0x4016f2  xor  eax, ecx                       ; ct2[i] ^ key8[i%8]
0x40170e  cmp  dl, al                         ; 逐字节比较
```

**公式：** `passB[i] = ct2[i] ^ key8[i % 8]`，`i = 0..13`

数据表：

- `ct2  @ 0x4b9010`：`02 6c 93 01 f0 38 ca 6c 79 11 f1 45 a7 6c`
- `key8 @ 0x4b9020`：`5a 23 c1 77 91 4d a6 18`

解出：`XORvault#2026!`（与 Hint "repeating XOR key, then use CyberChef" 对应；CyberChef `XOR key 5a23c177914da618` 得到同样结果）。

## 5. Flag 生成（`generate_flag @ 0x401730`）

**与两阶段输入、时间均无关，纯静态。** 这是本题真正的核心。

```asm
0x401742  mov  byte [rbp-0x19], 0x5a          ; 'Z'
0x401789..0x401798
          lea  eax, [edx*2 + edx]             ; i*3
          add  eax, 0x11
          xor  eax, 0x5a                      ; key_i
0x40179e  lea  rdx, [rip+0xb789b]             ; ct @ 0x4b9040
0x4017af  xor  al, byte [rbp-0x29]            ; ct[i] ^ key_i
0x4017bf  mov  byte [buf+i], cl
; 生成 0x28 = 40 字节后由 main 打印
```

**公式：** `flag[i] = ct[i] ^ ((i*3 + 0x11) ^ 0x5A)`，`i = 0..39`

数据表：

- `ct @ 0x4b9040`（40B）：
  `031a1803133c02180a18140506013e007e7c68774872667e5c75715958576e5744435d4c42aebca1`

## 8. 与前作「进击的x64(1)」对比

前作是 `xor eax,eax; ret` 壳 + .rdata 反向 base64；本作换成两阶段口令门（动态 seed + 循环 XOR）+ 位置相关 XOR 的 flag 生成。套路一致：**flag 本体永远是静态数据变换，口令只是门**。
