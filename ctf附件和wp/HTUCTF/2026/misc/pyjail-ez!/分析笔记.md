## 三、已排除的路线（全部实测）

### 1. 「跳进操作数」走私 —— **在 3.10 行不通**
想法：把被禁 opcode 放在奇数 offset，用 `JUMP_ABSOLUTE` 跳过去执行（dis 只按 2 字节步进解析偶数 offset）。

实测（3.10）：
- `JUMP_ABSOLUTE 4` → 跳到字节 offset **8**
- `JUMP_ABSOLUTE 2` → 跳到字节 offset **4**

即 **oparg 是 code unit 索引（字节偏移 = 2×oparg）**，跳转目标**永远偶数对齐**，无法错位。
强行跳到奇数会把后面的字节当 opcode 执行 → 立刻 **segfault**。

### 2. CACHE / inline cache 走私 —— **3.10 根本不存在**
- `opcode.CACHE` 在 3.10.20 上 `AttributeError`（3.11 才引入）
- `opcode` 模块无 `_inline_cache_entries`
- `dis` 输出是连续 2 字节指令，没有 cache 空洞可藏

### 3. dis 源码审计 —— 无解析/执行不一致
3.10 `dis._unpack_opargs`：固定 `range(0, len(code), 2)`，遇到未知 opcode（如 0）会
yield opname `'<0>'`（不在黑名单，能过 check），但**解释器执行 opcode 0 会 segfault**。
`EXTENDED_ARG` 的 arg 累积逻辑与 ceval 一致。

### 4. 嵌套 code object 藏 co_consts —— **能绕过检查，但执行不了**
`co_consts = ((nested_code,),)` 可以绕过 `any(isinstance(c, types.CodeType) ...)`（tuple 不是 CodeType）。
但 code object **不是 callable**（`callable(code_obj) is False`），所以：
- `CALL_FUNCTION` / `CALL_FUNCTION_EX` / `CALL_FUNCTION_KW` 都调不动
- 创建函数的 opcode 只有 `MAKE_FUNCTION`（禁）和 `LOAD_BUILD_CLASS`（禁）
- `exec`/`eval`/`open` 都没有（`__builtins__` 是 None）

### 5. 属性访问原语全部被封死（关键瓶颈）

业界常用技巧：**`IMPORT_FROM` 就是 `LOAD_ATTR` 的马甲**
（LA CTF 2023 `Pycjail`，同为 3.10：`IMPORT_FROM` 内部就是 `PyObject_GetAttr(TOS, names[i])`）。
**但本题把 `IMPORT_FROM` 一起禁了**，这条路封死。

于是盘点 3.10 所有能做属性访问的 opcode：

| opcode | 属性名来源 | 本题是否可用 |
|---|---|---|
| `LOAD_ATTR` / `LOAD_METHOD` / `IMPORT_FROM` | co_names | **禁** |
| `STORE_ATTR` / `DELETE_ATTR` | co_names（空 tuple → `GETITEM` 越界读，不可控） | 禁/不可控 |
| `MATCH_CLASS` | **栈上的 tuple（我们可控！）** 唯一不依赖 co_names 的 | 但**第二个参数必须满足 `PyObject_IsInstance(subject, type)`，即必须是真 type**；marshal 带不了任何 type 对象 → 死路 |
| `SETUP_WITH` / `WITH_EXCEPT_START` / `BEFORE_ASYNC_WITH` / `GET_AWAITABLE` / `GET_AITER` / `GET_ANEXT` | 硬编码 `__enter__` / `__exit__` / `__aenter__` / `__await__` / `__aiter__` / `__anext__` | 数据常量没有这些属性 |
| `MATCH_KEYS` / `COPY_DICT_WITHOUT_KEYS` | 硬编码 `get` / `keys`（dict 走 `PyDict_CheckExact` 快路径，不触发属性） | 数据常量没有 |

### 6. 常量里能有什么（实测 marshal，36 种对象）

**可序列化**：`int/float/complex/str/bytes/bool/None/Ellipsis/StopIteration/tuple/list/set/frozenset/dict/bytearray/memoryview/code`
**不可序列化**：`type`（int、object、CodeType、FunctionType）、`function`（print、lambda）、
`builtin`（len）、`module`（sys）、`super`、`staticmethod/classmethod/property`、
`range`、`iter`、`object()`、`method`、generator …

→ 常量里**唯一"活"的对象是 code object**，而 `callable(code_obj) is False`（已实测），
`hasattr(code,'__call__') is False`。所以 `CALL_FUNCTION/EX/KW` 全调不动它。

## 四、待探索方向

1. **能触发 Python 层调用的 opcode**（需要一个"活对象"在栈上，而常量里唯一的活对象是 code object）：
   `PRINT_EXPR`（调 `sys.displayhook`）、`FORMAT_VALUE`/`BUILD_STRING`、`SETUP_WITH`/`WITH_EXCEPT_START`、
   `BEFORE_ASYNC_WITH`、`GET_AWAITABLE`、`FOR_ITER`/`UNPACK_SEQUENCE`、`MATCH_*`（3.10 新增，
   `MATCH_CLASS` 会读 `__match_args__`）。
2. **`co_freevars` / `co_cellvars` 不受 check 限制**（只限制了 `co_nlocals==0`、`co_varnames` 为空）：
   `LOAD_DEREF` / `STORE_DEREF` / `DELETE_DEREF` / `LOAD_CLASSDEREF` / `COPY_FREE_VARS` **均不在黑名单**。
   研究 3.10 frame 初始化：无闭包时 cell 是否为 NULL？能否 `STORE_DEREF` 存 code object 再让解释器调用它？
3. **`STORE_ATTR` / `DELETE_ATTR` 也不在黑名单**（只禁了 `LOAD_ATTR`）。`co_names` 为空时
   `GETITEM(names, 0)` 在 release 版无边界检查，会越界读——能否通过内存布局让它读到可控内容？
4. **信息泄露**：jail 会把 `traceback.format_exc()` 打到 stdout；嵌套 code object 的
   `co_filename` 完全可控，可出现在 traceback 里。
5. **题目提示**：「我们说 pyjail ez 的那个源头是什么？是 crazyman 吗？不！是牛来！」
   ——「crazyman」应是某个 pyjail 集合项目；「牛来」含义未解（谐音 newbie / newline？）。
