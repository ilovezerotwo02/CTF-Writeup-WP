## 0. 题目源码

```python
from secret import flag
import gmpy2, decimal
from Crypto.Util.number import *

def gethint(h,p):
    decimal.getcontext().prec = 1024
    H = decimal.Decimal(int(h)); P = decimal.Decimal(int(p))
    leak = decimal.Decimal((8*H*P - 1) / (16*P*P))
    return leak

p = getPrime(512); q = getPrime(512); f = getPrime(512); g = getPrime(128)
h = gmpy2.invert(f, p) * g % p          # h = g·f⁻¹ mod p  ← NTRU 公钥

n = f*q                                  # RSA 模数（注意不是 p*q！）
e = 65537
c = pow(bytes_to_long(flag), e, n)
print('c =', c); print('hint =', gethint(h,p)); print('n =', n)
```

关键观察：

* `p` 只是 **NTRU 模数**，和 RSA 模数 `n = f·q` 没有任何公因子；
* `h = g·f⁻¹ mod p` 是**维度为 1 的 NTRU**，私钥是 `(f, g)`，其中 `g` 只有 128 bit；
* 只要拿到 `f`（或 `q`），`n` 就分解完成，剩下就是普通 RSA 解密。

## 1. 从 hint 恢复 `p` 和 `h`（连分数）

```
leak = (8hp - 1) / (16 p²)     ← 分子分母都是 ~1028 bit 的有理数
```

`Decimal` 只输出 **1024 位有效数字**，即绝对误差约 `10⁻¹⁰²⁴ ≈ 2⁻³⁴⁰⁵`。

有理数 `a/b` 能作为连分数收敛子被恢复出来的条件是误差 `< 1/(2b²)`；这里
`b = 16p² ≈ 2¹⁰²⁸`，需要误差 `< 2⁻²⁰⁵⁷`，而实际有 `2⁻³⁴⁰⁵` —— 精度绰绰有余。

所以直接对 `Fraction(Decimal(hint_str))` 做连分数展开，逐个收敛子 `A/B` 检验：

```
B % 16 == 0 且  B/16 是完全平方数  →  p = isqrt(B/16)
(A+1) % (8p) == 0                   →  h = (A+1)/(8p)
```

实测第 606 个收敛子命中：


## 2. 把 NTRU 关系翻译成「`n` 的某个因子 + 小未知数」

### 2.1 为什么普通 NTRU 格攻击打不动

由 `h = g·f⁻¹ mod p` 得 `f·h ≡ g (mod p)`，即 `(f, g)` 在格
`L = {(x,y) : y ≡ h·x (mod p)}`（`det L = p ≈ 2⁵¹²`）里。

但这里 `|f| ≈ 2⁵¹² ≈ p`、`|g| ≈ 2¹²⁸`，而 `L` 的最短向量只有 `≈√p = 2²⁵⁶`。
盒子 `|x|≤2⁵¹² , |y|≤2¹²⁸` 里有 `≈2¹³⁰` 个格点 —— **(f,g) 根本不是短向量，LLL 找不到它**。
（等价于说：`f·h mod p < 2¹²⁸` 这个条件只把 `f` 的候选从 `2⁵¹²` 缩到 `2¹²⁸`，还差 128 bit。）

必须把 `n = f·q` 这条信息一起用上。

### 2.2 关键一步：构造 `S = j + l·q`

`f·h ≡ g (mod p)`，两边乘 `q`（记住 `f·q = n`）：

```
n·h ≡ g·q  (mod p)
```

记 `R := n·h mod p`，则存在整数 `j` 使

```
g·q = R + j·p        ,    j ≈ g·q/p ≈ 2¹²⁸   （约 128 bit，很小！）
```

把上式对 `q` 取模，注意 `g·q ≡ 0 (mod q)`：

```
j·p ≡ -R  (mod q)   ⟹   j ≡ -R·p⁻¹  (mod q)
```

`p⁻¹` 这里是对 **`n`** 取逆（`p` 与 `n` 互素，因为 `n = f·q` 的两个因子都与 `p` 无关），于是令

```
S := (-R · p⁻¹) mod n
```

由于 `q | n`，把 `S` 再对 `q` 取模就得到 `j`，因此

```
S = j + l·q      ,  0 ≤ l < f
```

**结论：多项式 `F(x) = x - S` 在 `n` 的未知因子 `q`（`q ≈ n^{1/2}`）上有一个小根 `x = j`，且 `|j| ≈ 2¹²⁸`。**

这正是 Howgrave-Graham「未知因子上的小根」问题。可用性判据：`q ≥ N^β (β=1/2)`、`F` 次数 `δ=1` 时，可求解 `|j| < N^{β²/δ} = N^{1/4} = 2²⁵⁶`。
而 `|j| ≈ 2¹²⁸` —— **富余 128 bit**，格可以取得很小。

## 3. Howgrave-Graham 格 + LLL 求 `j`

取 `X = 2¹³²`（`|j|` 上界），构造多项式族（`m, t` 为参数）：

```
g_k(x) = N^{m-k} · (Xx - S)^k      k = 0..m
h_r(x) = (Xx)^r · (Xx - S)^m       r = 1..t
```

在 `x = j` 处它们都被 `q^m` 整除（`F(j) ≡ 0 mod q`，且 `N ≡ 0 mod q`）。
把每个多项式按 `x⁰..x^{m+t}` 的系数排成行向量，得到 `(m+t+1)` 维格；
LLL 后取最短的几个行向量还原成整系数多项式，两两取 `gcd` 即得一次因式 `(x - j)`。

Howgrave-Graham 条件：`‖b‖ < q^m / √dim`。
本例 `m=t=1`（3 维）就已满足：`det = N·X³ ≈ 2¹⁴²⁰`，`det^{1/3} ≈ 2⁴⁷³ < q = 2⁵¹²`。
LLL 只用 0.3 秒：

```
j = 208088412835054207487583314973649529591     (128 bit)
```

于是

```

f = n / q        = 11940825708159550087309130022215170999099109396704605237103082796561952392268200064739442507670605370304389549433933758696849048940342961045633256599474617
```

校验：`g = f·h mod p = 204784646316350019572393778827599262903`（正好 128 bit），
且 `g·f⁻¹ mod p == h` ✓ —— 说明 `f` 确实是 NTRU 私钥。

## 6. 踩坑记录

1. **不要指望 NTRU 格**：`f ≈ p` 时 `(f,g)` 不是短向量（差约 2¹³⁰ 倍），必须结合 `n`。
2. `p⁻¹` 要对 `n` 取模，不是对 `q`（`q` 还不知道）。
3. `X` 不能乱取大：`X` 越大格条件越难满足，取 `j` 真实上界附近最好（本题 `j` 128 bit，取 `2¹³²`）。
4. 还原多项式时系数是**升幂/降幂**要分清；取根用「两个短向量多项式求 gcd」，
   不要用 `ground_roots()`（它需要分解巨大的常数项，会卡死）。
