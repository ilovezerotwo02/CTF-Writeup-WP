## 1. 题目在干什么（读 gen.py）

点集是**高斯素数的格点**，两点相邻当且仅当切比雪夫距离 ≤ D：

```python
def adj(p, q):
    return max(abs(p[0]-q[0]), abs(p[1]-q[1])) <= D
```

出题流程：

1. `build_cycle` 造一条长度 `TARGET` 的**有序**路径，首尾相邻收口成环；过程中允许加少量"弦"（chord）。
2. 把这条环随机旋转 `k` 位，用 `route_bytes` 序列化后算密钥流：

```python
seed = sha256(b"HTUCTF|" + route_bytes(route))
ks[i] = sha256(seed + i.to_bytes(4,'big')).digest()[0]
ct = flag XOR ks
```

3. 再往点集里塞一堆干扰：若干条小环（`N_FAKE`）、挂在环上的吊坠（`N_PENDANT`）、吊坠再接吊坠（`N_CHAIN`），最后打乱顺序。

所以 `attack.json` 里 94 个点、密文 44 字节（=> flag 长 44，环长必须 ≥44）。

## 2. 先定 D 和结构

对 D=1..10 各建图看连通块：

```
D=5  main=15  comps=[15,6,6,5,5]
D=6  main=57  comps=[57,16,12,9]   ← 主块 57，其余是小环（干扰）
D=7  main=57  comps=[57,16,12,9]
```

因为 flag 长 44，真环必须 ≥44 个点，只可能落在 57 那块里 → **D = 6**。

主块 57 = 真环 + 5 个吊坠（2-core 之外）。

## 3. 坑：它不是哈密顿环

第一反应是在 2-core（52 点 / 72 边）上找哈密顿环，结果 **一条都搜不出来**：
用"每个未访问点至少还要有 2 个可用邻居"的剪枝，从第一个点出发就把所有分支剪死了
（`hsolve2.py` 里 `tested cycles 0`）。

原因：真环上挂了 20 条弦，2-core 里的点集比真环大，核心图是「环 + 多条平行链」的 theta 结构，
不存在遍历全部 52 个 core 点的哈密顿环。

## 4. 正解：枚举长环 + 明文前缀当 oracle

关键点：**明文开头 7 字节是已知的 `HTUCTF{`**，而 keystream 只依赖整条路线，
所以只要把候选环逐条喂进去、用这 7 个字节判定，就能一击命中。

```python
seed = sha256(b"HTUCTF|" + route_bytes(route))
ks = [sha256(seed + i.to_bytes(4,'big')).digest()[0] for i in range(7)]
assert bytes(c ^ k for c, k in zip(ct, ks)) == b"HTUCTF{"
```

搜索：

- 在 57 点主块上做 DFS 枚举**简单环**，长度 ≥ 44；
- 用 `w > s0` 的规范起点去重（每个环只算一次）；
- 剪枝：`len(path) + 剩余点数 < 44` 直接回。
- 每个候选环再试 **52 个旋转 × 2 个方向**（因为出题方随机旋转过）。

## 5. 一句话总结

题目把密钥流绑在"一条有序长环"上，干扰环/吊坠只是噪声；
真环藏在 57 点的主连通块里，用已知明文 `HTUCTF{` 当 oracle 枚举长环即可一击命中。
注意别被 2-core 带偏——有弦的图不存在哈密顿环。
