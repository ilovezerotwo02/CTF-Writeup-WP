# InvisibleLeak WP

## 题目信息

- 题目：InvisibleLeak
- 分类：数据安全

## 附件概览

解压后得到 3 个核心文件：

- `poster.png`
- `notice.docx`
- `exfil_tool.pyc`

结合题目描述，这 3 个文件明显对应一条“分片藏密钥 + 最终解密”的外泄链。

## 1. 逆向 `exfil_tool.pyc`

先识别 `.pyc` 版本并反汇编，可以恢复出几段关键逻辑：

### `_0x1a3c(img, N)`

对图片做 `N` 轮像素置乱，映射关系为：

```python
nx = (x + y) % W
ny = (x + 2 * y) % W
```

这就是经典 Arnold Cat Map 风格置乱，用来打散图片内容。

### `_0x2b7f(img, data)`

把数据前面补一个 4 字节大端长度，然后逐 bit 写入 RGB 三个通道的最低位，也就是典型 LSB 隐写。

### `_0x3c9e(text, map)`

只提取文本中的 4 类零宽字符：

- `U+200B -> 00`
- `U+200C -> 01`
- `U+200D -> 10`
- `U+FEFF -> 11`

按 2 bit 一组拼接后还原字节流。

### `_0x4f3a(data, key)`

核心加解密逻辑：

1. 第 `i` 个字节先按 `i % 8` 做循环左移
2. 再与 `key[i % len(key)]` 做异或

解密时做逆操作即可：先异或，再循环右移。

### 常量

脚本里有一段十六进制密文：

```text
c76a46ef52b009aafebc2553a0939c4e95de0b1dd6509f00f81a74638093cb6698d44a758359
```

这就是最终需要解出的敏感数据。

## 2. 分析 `notice.docx`

把 `word/document.xml` 解出来后，可以发现正文里混入了 32 个零宽字符。

按脚本里的映射还原后，得到：

```text
c9d0e1f2a3b4c5d6
```

这是 8 字节密钥分片。

## 3. 分析 `poster.png`

根据 `_0x1a3c` 可知海报被做过 7 轮置乱，所以先做逆置乱，再按 `_0x2b7f` 的反过程从 RGB LSB 中提取载荷。

提取结果不是文本，而是一张内嵌 PNG。打开后是一枚二维码。

二维码内容为：

```text
a1b2c3d4e5f60718
```

这又是另一个 8 字节密钥分片。

## 4. 还原完整外泄链路

外泄工具的设计可以还原为：

1. 用 `_0x4f3a` 对目标敏感数据做“循环位移 + 异或”加密
2. 把密文硬编码进 `exfil_tool.pyc`
3. 把密钥拆成两半
4. 第一半做成二维码图片，再用 LSB 写进 `poster.png`
5. 为了进一步规避肉眼识别，再对海报执行 7 轮 Arnold 风格置乱
6. 第二半藏进 `notice.docx` 的零宽字符里
7. 两份普通办公文件各自看起来都很正常，因此 DLP 难以仅凭明文内容或常规传输特征发现异常

## 5. 拼接密钥并解密

按恢复出的顺序，完整密钥为：

```text
a1b2c3d4e5f60718c9d0e1f2a3b4c5d6
```

也就是字节序列：

```text
a1 b2 c3 d4 e5 f6 07 18 c9 d0 e1 f2 a3 b4 c5 d6
```

对脚本中的密文执行逆变换后，得到：

```text
flag{28e761409e1462935b01ee2298a93b4f}
```

## 最终 Flag

```text
flag{28e761409e1462935b01ee2298a93b4f}
```
