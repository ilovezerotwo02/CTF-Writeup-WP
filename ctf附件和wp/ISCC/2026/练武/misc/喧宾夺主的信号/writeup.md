# 喧宾夺主的信号 — MISC 解题报告

## 题目分析

题目提供 `attachment-17.pcapng` 网络流量包。提示语引用"声东击西"（三十六计第一套第六计），暗示真正的攻击隐藏在看似不重要的地方。

## 解题步骤

### 1. 流量概览

使用 Scapy 读取 pcap 文件，共 1509 个包：
- **1500 个 UDP 包** — 全部发往 `239.255.255.250:1900`（SSDP 组播），每包 28 字节 payload
- **9 个 TCP 包** — `192.168.1.100` 与 `45.78.1.1` 之间的通信

**"声东击西"**：大量 UDP 组播是"东"（故意制造的噪声），而少量 TCP 通信才是"西"（真正的攻击指令）。

### 2. 从 TCP 中提取隐藏数据

过滤 TCP 包中带 Raw 载荷的包，发现一个 HTTP POST 请求：

```
POST /command HTTP/1.1
Host: 45.78.1.1
Content-Type: application/json
Content-Length: 680

{"instruction": "UEsDBBQAAQA...", "note": "This is the real command."}
```

`instruction` 字段为 base64 编码数据，解码后得到一个 AES 加密的 ZIP 文件，内含 `image.png`。

### 3. 从 UDP 组播噪声中提取 ZIP 密码

提示："或许在那些看似无意义的广播中，藏着打开真正宝藏的钥匙。"

遍历 1500 个 UDP 包，发现其中 4 个包的 base64 payload 包含 `=` 填充符（位置 200、500、800、1100），内容完全相同：

```
U2hlbmdEb25nSmlYaUAzNi0xLTY=
```

解码后得到：**`ShengDongJiXi@36-1-6`**
- `ShengDongJiXi` = "声东击西"拼音
- `36-1-6` = 三十六计第一套第六计

### 4. 解密 ZIP 获取图像

使用该密码解密 ZIP，得到 `image.png`（100×100 像素，RGB 模式）。

图像仅包含 **8 种颜色**，RGB 各通道值相差仅为 1（如 72/73、108/109、136/137），这是典型的 **LSB（最低有效位）隐写**特征。

### 5. LSB 提取 Flag

8 种颜色正好编码 3 bit/像素（R、G、B 各 1 bit），每 3 bit 对应一个像素。

提取方法：遍历所有像素，取每个通道的 LSB（`pixel & 1`），按 R→G→B 顺序排列，每 8 bit 组成一个字节：

| 颜色值 | R LSB | G LSB | B LSB |
|--------|-------|-------|-------|
| (72,108,136) | 0 | 0 | 0 |
| (72,108,137) | 0 | 0 | 1 |
| (72,109,136) | 0 | 1 | 0 |
| (72,109,137) | 0 | 1 | 1 |
| (73,108,136) | 1 | 0 | 0 |
| (73,108,137) | 1 | 0 | 1 |
| (73,109,136) | 1 | 1 | 0 |
| (73,109,137) | 1 | 1 | 1 |

最终得到 Flag：

```
ISCC{1d3f1c44t10n_1s4_th3_k3y_t0_v1cmtc0Fry}
```

## 总结

| 步骤 | 关键点 | 工具 |
|------|--------|------|
| 流量分析 | "声东击西"：UDP 是噪声，TCP 是真实攻击 | Scapy |
| ZIP 提取 | 从 TCP POST 请求中提取 base64 → AES 加密 ZIP | - |
| 密码获取 | UDP 组播中 4 个含 `=` 的包，解码得密码 | base64 |
| 图片解密 | AES ZIP 解密 → 100×100 LSB 隐写图像 | pyzipper |
| Flag 提取 | RGB 三通道 LSB 组合成字节 | Pillow |
