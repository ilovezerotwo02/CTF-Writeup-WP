# QuorumGlyph

## 文件清单

本目录只需要下面三个文件：

- `/QuorumGlyph`
- `/description.txt`
- `/exp.py`

最终目的很直接：从 `/QuorumGlyph` 里恢复出正确的 `ISCC{...}`。

## 先别急着盯字符串

这题最容易做错的一步，就是看见程序只回 `Yes???` / `No???`，就默认它是普通的本地比较器。  
如果沿着这个思路死扣 `memcmp`，会很快发现信息一直不完整。

题面那句：

```text
One witness lies. Two are incomplete. Three agree.
```

更合理的理解方式不是“有假 flag”，而是：

- 程序内部有多组独立的校验信号
- 其中两组并不会给出完整答案
- 只有把它们拼起来，才会得到完整输入

## 先把输入轮廓固定下来

从 `main` 的外层检查开始，能够很快确认三件事：

1. 总长度固定为 `42`
2. 头部锁死为 `ISCC{QRM_`
3. 末尾会落到 `_3_w1tness_no_single_path!!}`

所以这题的未知量其实不大，真正麻烦的是中间那段是被拆开验证的，而不是一次性比较。

## 三段校验分别在干什么

程序里有三段核心逻辑：

### 第一段

按 `42` 个位置循环处理，把输入折成 6 个 `qword`，做一轮按位奇偶校验。

### 第二段

把输入重排成 16 个 `u32`，再做 37 轮变换，最后和运行时目标块比对。

### 第三段

单独拿中间 5 个字符，把它们编码成一个 `24-bit` 值，再丢给另一套哈希流程。

这里最值钱的观察是：

**前两段都会先把中间 5 个字符清零。**

换句话说，它们从一开始就不打算告诉你完整答案，只负责把“大框架”钉住。

## 先还原外壳，再补中间缺口

因为第二段比第一段更像“可逆变换”，最适合拿来做反推。  
而且它用到的目标值并不是静态写死的，是构造器先往 `.bss` 里灌进去的。

所以稳定路线是：

1. 先把构造器跑起来
2. 读取运行时目标值
3. 再把第二段逆回去

这样处理以后，能得到一个很关键的骨架：

```text
ISCC{QRM_....._3_w1tness_no_single_path!!}
```

这时事情就清楚了：

- 外层和尾巴已经都被锁死
- 剩下只有正中间 5 个字符没补上

## 中间 5 个字符不是猜出来的

第三段只看这 5 位，而且它们不是任意字符，而是来自一个 32 字符集合：

```text
ABCDEFGHJKLMNPQRSTUVWXYZ23456789
```

程序会先把这 5 个字符打包成一个 `24-bit` 整数 `x`，然后做一次仿射映射：

```text
y = ((x - 0xb3ef33) * 0x989b19bd) mod 2^24
```

再把 `y` 送进独立哈希分支。

因为搜索空间只有 `2^24`，这里与其猜词，不如直接把整段逻辑翻译出来跑一遍。  
扫完以后只会命中一个结果：

```text
middle = FE6V6
```

把它补回骨架以后，完整输入就出来了：

```text
ISCC{QRM_FE6V6_3_w1tness_no_single_path!!}
```

## 为什么可以确认这就是最终答案

只靠“看起来像 flag”还不够，这题最好再走一次真实程序闭环。

这里的做法是用 Unicorn 模拟：

- 先执行构造器
- 再执行真实 `main`
- 只对少量导入函数做 hook：`puts / strlen / strchr / memcmp / scanf`

把候选串送进去后，会拿到：

```text
input flag: -> Yes???
```

如果把 `FE6V6` 改错任意一位，程序就会走到：

```text
input flag: -> No???
```

这一步很重要，因为它说明当前结果不是“某层逻辑单独对上”，而是整个检查链真的闭合了。

## 使用方法

直接在当前目录运行：

```bash
python ./exp.py
```

或者把附件路径显式传进去：

```bash
python ./exp.py ./QuorumGlyph
```

脚本会自动完成：

1. 提取运行时目标值
2. 回滚第二段，拿到骨架
3. 穷举第三段的 `24-bit` 缺口
4. 再模拟一次真实 `main`

## 这题真正的坑

### 坑一：把所有 witness 都当成完整信息源

前两段其实天然是残缺的，它们只能把外壳拼出来，不能单独恢复完整答案。

### 坑二：静态看到目标块就停

构造器写进 `.bss` 的那些值不是明文，而是比较层的中间目标。  
如果在这里停住，方向会错得很彻底。

### 坑三：把中间 5 位当成猜词题

这 5 个字符确实很短，但真正可靠的做法仍然是按程序逻辑搜索，而不是拍脑袋补词。

## 最终 flag

```text
ISCC{QRM_FE6V6_3_w1tness_no_single_path!!}
```
